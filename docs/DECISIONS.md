## 2. Задача клиента

Radal участвует в тендерах на нескольких площадках. Главные боли (в порядке приоритета):

1. **Пропускаем релевантные тендеры** — нет автоматического мониторинга
2. **Тратим много времени на ручной разбор ТЗ** — менеджер вручную ищет совпадения с каталогом
3. **Нет аналитики по выигрышам/проигрышам** — не видно паттернов
4. **Дублируем усилия** — одна и та же позиция на разных площадках

## 3. Архитектура: 7 слоёв

### Слой 1 — Data sources
- **TenderGuru** — основной агрегатор, подписка на ОКПД2 26.11/26.12/26.20/26.51/27.11-27.12
- **B2B-Center** — второй источник, через API или парсинг
- **Каталог Radal** — CSV из 1C, обновление раз в сутки. До получения реального каталога используется seed-каталог (15 позиций)

### Слой 2 — Part number extraction + normalization
- **PN extractor** — regex + стоп-лист + Siemens-style join
- **MFR detector** — 200+ алиасов
- **Param extractor** — regex для V, A, W, MHz, корпус

**Решение:** Natasha НЕ используется как ядро. Для электроники главный идентификатор — part number, а не свободный текст.

### Слой 3 — Scenario router
- **A (~70%)** — найден PN → exact matching
- **B (~20%)** — категория + параметры → параметрический matching
- **C (~10%)** — общее описание → категорийный matching

### Слой 4 — Splink matching engine
- **Blocking:** 4 правила (PN prefix → category+MFR → category+voltage → category)
- **Веса:** PN 60%, MFR 20%, Category 8%, Voltage 4%, Current 4%, Name 4%
- **Backend:** DuckDB

### Слой 5 — LLM-judge
- **Зона:** borderline 0.75–0.92 (~10-15% пар)
- **Модель:** GigaChat Max / YandexGPT
- **Fallback:** таймаут 5 сек → ручная очередь

### Слой 6 — Relevance ranking
- Match quality 40% + Stock availability 25% + Margin 20% + Deadline urgency 15%

### Слой 7 — Dashboard + alerts
- **MVP:** Streamlit / HTML (4 экрана)
- **Alerts:** Telegram-бот

## 4. Ключевые технические решения

### Part Number как главный ключ
Для электроники ключ — part number (CM1000E3U-34NF), а не свободный текст. Exact match вместо fuzzy.

### Отказ от Natasha как ядра
Лемматизация русских слов не нужна, когда главный идентификатор — буквенно-цифровой код.

### Отказ от пайплайна для труб/металлопроката
Весь пайплайн из исходных документов GoldenMatch v1/v2 (ГОСТ, материал, размеры) удалён.

### Seed-каталог вместо ожидания
15 позиций из открытых источников позволяют вести разработку всех 7 слоёв параллельно.

### TenderGuru без LLM-парсера
Структурированные данные, PN извлекаются regex.
